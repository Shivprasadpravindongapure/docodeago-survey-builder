  ├── GET  /api/surveys             — list user's surveys [AUTH]

  ├── POST /api/surveys/:id/questions      — add question [AUTH]

🗄️ Database Schema (Cloudflare D1)

CREATE TABLE users (
  id           TEXT PRIMARY KEY,   -- nanoid
  email        TEXT UNIQUE NOT NULL,
  password_hash TEXT,              -- PBKDF2-SHA256 · 100k iterations (nullable = magic-link only)
  created_at   TEXT DEFAULT (datetime('now'))
);

CREATE TABLE surveys (
  id          TEXT PRIMARY KEY,
  user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title       TEXT NOT NULL DEFAULT 'Untitled Survey',
  description TEXT,
  brand_color TEXT NOT NULL DEFAULT '#6366f1',
  logo_url    TEXT,
  created_at  TEXT DEFAULT (datetime('now'))
);

CREATE TABLE questions (
  id        TEXT PRIMARY KEY,
  survey_id TEXT NOT NULL REFERENCES surveys(id) ON DELETE CASCADE,
  type      TEXT NOT NULL,          -- short_text | long_text | multiple_choice | rating | ...
  label     TEXT NOT NULL,
  options   TEXT,                   -- JSON array of strings, nullable
  position  INTEGER NOT NULL DEFAULT 0,
  required  INTEGER NOT NULL DEFAULT 0  -- 0 or 1
);

CREATE TABLE responses (
  id          TEXT PRIMARY KEY,
  survey_id   TEXT NOT NULL REFERENCES surveys(id) ON DELETE CASCADE,
  submitted_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE response_answers (
  id          TEXT PRIMARY KEY,
  response_id TEXT NOT NULL REFERENCES responses(id) ON DELETE CASCADE,
  question_id TEXT NOT NULL,
  value       TEXT NOT NULL          -- checkbox answers joined with |||
);

🔐 Auth Flow

NEW USER — First visit:
  1. Enter email → POST /auth/check-email → { exists: false }
  2. Show "Create account" → POST /auth/magic-link
  3. Brevo sends email with link: /verify?token=xxxxx
  4. Click link → POST /auth/verify → creates session in KV (30-day TTL)
  5. API sets cookie: session=xxx; HttpOnly; Secure; SameSite=None; Path=/
  6. window.location.href = '/dashboard' (hard redirect, not React navigate)

RETURNING USER WITH PASSWORD:
  1. Enter email → check-email → { exists: true, hasPassword: true }
  2. Show password field → POST /auth/login → PBKDF2 verify → session → cookie
  3. navigate to /dashboard

RETURNING USER (magic link only):
  1. check-email → { exists: true, hasPassword: false }
  2. Offer magic link OR set password from dashboard first
  3. Same verify flow as new user

SET PASSWORD (from dashboard):
  1. Avatar menu → "Set Password" → modal
  2. POST /auth/set-password → hash with PBKDF2 → store in D1
  3. Next login can use password directly

🧠 6 Key Technical Decisions

🔑
PBKDF2 WebCrypto

Cloudflare Workers has no Node.js crypto module. Used native Web Crypto API — PBKDF2 + SHA-256, 100k iterations, constant-time comparison. Zero bcrypt dependencies. Works at the edge.

🌐
Dynamic CORS Origin

Each Cloudflare Pages deploy gets a unique preview subdomain (abc123.pages.dev). Static origin list would block every preview. Wrote an origin function: accept any *.pages.dev.

🔗
Hard Redirect After Magic Link

React Router's navigate() does not flush the cross-origin cookie context. window.location.href does — forces a full browser navigation that picks up the new Set-Cookie header.

📧
Brevo over Resend

Resend free tier only sends to your own verified domain — unusable for sending magic links to any user's email. Brevo sends to anyone, 300 free emails/day, simple HTTP API.

🗃️
Cloudflare D1 SQLite

Serverless SQLite at the edge. No connection pooling, no cold start penalty, generous free tier (5 GB). D1 runs in the same data centre as the Worker — near-zero latency queries.

📄
window.print() for PDF

No jsPDF, no Puppeteer, no lambda. Generate HTML in a popup window with inline styles, brand colors, numbered Q&A. Call window.print() after 400ms. Works in every browser. Zero dependencies.

💡 One Thing I'd Do Differently

ProblemCurrent ApproachBetter Approach
Cross-origin cookies being phased out by browsers (third-party cookie deprecation) API on workers.dev domain, frontend on pages.dev domain — different origins require SameSite=None cookies Serve the API as a Cloudflare Pages Function under the same pages.dev domain (/functions/api/*) — same-origin, SameSite=Strict, no cross-origin cookie issues
